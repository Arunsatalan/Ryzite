## B. Admin Dashboard Full Inventory

### 1. Admin Navigation
- **Tabs:** CRM (Leads), Services CMS, Projects, Blogs, SEO, Analytics.
- **Functionality:** Driven by local state `activeTab`.

### 2. Leads / CRM
- **Status:** MISSING/BROKEN.
- **Features:** Tries to fetch from `/api/leads`, but the API route doesn't exist, resulting in a 404 HTML response which crashes the JSON parser.

### 3. Services CMS
- **Status:** PARTIAL.
- **Features:** Renders list of services passed via props from `HomePageClient`. Has a form to create a new service, but it only captures Title and Description. Saving updates the `HomePageClient` state, but does not use an API or Database.

### 4. Projects CMS
- **Status:** PARTIAL.
- **Features:** Displays projects passed via props. Edit/Delete logic updates local state only.

### 5. Blog CMS
- **Status:** PARTIAL.
- **Features:** Displays blogs passed via props. Edit/Delete logic updates local state only.

### 6. SEO Module
- **Status:** PARTIALLY CONNECTED (to memory store).
- **Features:** Page selector (Home, Services, Solutions, Portfolio, About, Blog, dynamic routes). Fetches from and saves to `/api/seo`, which updates the in-memory `store.service.ts`. Includes a SERP simulator and Schema JSON generator.

### 7. Analytics
- **Status:** MISSING/BROKEN.
- **Features:** Tries to fetch from `/api/analytics/summary`, but the API route doesn't exist (returns 404).

## C. Backend / API / Data Inventory

### API Routes
- `/api/seo` (GET, PUT) - Connects to `store.service.ts`.
- `/api/services` (GET, POST) - Connects to `store.service.ts`. (Not actually used by the frontend).
- Missing Routes: `/api/leads`, `/api/analytics/summary`, `/api/projects`, `/api/blogs`.

### Data Store
- `server/services/store.service.ts`: An in-memory class containing arrays initialized from `initialData.ts`. Data is lost when the Next.js server restarts.

### Database
- Prisma schema exists but is currently disconnected from the actual application logic for these features.

### State Management
- `HomePageClient.tsx` holds `services`, `projects`, and `blogs` in React `useState`, initialized statically from `initialData.ts`. It does not fetch from the API.

## G. Admin Features That Exist But Are Not Connected
- **Services/Projects/Blogs APIs:** The APIs and `store.service.ts` methods exist, but `HomePageClient.tsx` does not fetch from them.
- **SEO Saved Data:** The Admin SEO tab saves data to `store.service.ts`, but the public pages (e.g., `app/page.tsx`) do not consume this data; they use hardcoded metadata exports.

---

## H. Completely Missing Admin Controls
- **Hero & Landing Text CMS:** No way to edit headers, descriptions, or CTAs.
- **FAQ CMS:** FAQs are strictly driven by `initialData.ts`.
- **Solutions CMS:** Solutions are driven by `initialData.ts` and not present in the Admin Dashboard.
- **AEO / About CMS:** No way to edit the company fact sheet or about principles.
- **Leads & Analytics APIs:** The UI expects them, but the backend routes are missing.
- **Site Settings:** No global controls for logos, contact emails, social links, or footer text.

---

## I. SEO Current Status
- **Home Page (`app/page.tsx`):** Uses a hardcoded `export const metadata` object.
- **Other Pages (`app/about/page.tsx`, etc.):** Most likely also using hardcoded exports or defaults.
- **Structured Data:** The `HomePageClient` renders a `<SeoStructuredData>` component, but passes `DEFAULT_PAGE_METADATA` directly from `initialData.ts`, ignoring anything saved in the Admin Dashboard.

---

## J. SEO Missing Controls
- **Server-Side Rendering (SSR) Integration:** Next.js Server Components need to fetch the SEO config from the database (or store) using the `generateMetadata` function to inject proper `<head>` tags before the page reaches the client.
- **Sitemap & Robots:** No dynamic `sitemap.xml` or `robots.txt` generators.

---

## K. Mock / Temporary Data Risks
- **Volatile State:** Because `HomePageClient` relies on local `useState` for CMS data, opening the site in a new tab reveals the original hardcoded data, hiding any changes made in the Admin Dashboard.
- **Memory Store:** `store.service.ts` loses all saved SEO data and any API-submitted changes the moment the Node process restarts.
- **Broken Endpoints:** The Admin Dashboard crashes or throws console errors due to missing `/api/leads` and `/api/analytics` endpoints returning 404 HTML pages that fail JSON parsing.

---

## L. Developer-Controlled Features
The following must remain in code and should NOT be moved to the Admin CMS:
- **Tailwind CSS & Layouts:** Component structures, grids, and responsive behaviors.
- **Animations & SVG Splashes:** Complex visual effects (e.g., Liquid Wave Dividers).
- **Consultation Wizard Logic:** Multi-step form state machine and validation rules.
- **Next.js Routing & Data Fetching Logic:** Server vs Client component boundaries.
- **Database Schema (Prisma):** Models and relationships must be managed via migrations.
- **Metadata Generation Engine:** The logic inside `generateMetadata` that maps DB fields to HTML tags.

---

## M. Recommended Connection Plan
1. **Database Migration:** Move `INITIAL_*` arrays from `initialData.ts` into a PostgreSQL database via Prisma.
2. **API Completion:** Build out missing API routes (`/api/leads`, `/api/analytics/summary`, `/api/projects`, `/api/blogs`, `/api/faqs`, `/api/solutions`) to interface with Prisma.
3. **Server Component Refactor:** Refactor `app/page.tsx` (and other routes) to be Server Components that fetch data directly from Prisma, passing the static data as props to the Client Components (removing the need for `useState` initialization).
4. **Metadata Refactor:** Implement Next.js `generateMetadata()` in `page.tsx` files to fetch SEO data from Prisma based on the current route.
5. **Admin Dashboard Refactor:** Update `AdminDashboard.tsx` to perform real `fetch` mutations against the new API routes, removing its reliance on passing state up to `HomePageClient`.
6. **Global Settings Model:** Create a new Prisma model for global site settings (Hero text, Footer links, AEO facts) and build a corresponding Admin tab.
